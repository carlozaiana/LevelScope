## What the three lanes mean

| Lane | Measured evidence | Interpretation |
| --- | --- | --- |
| Potential passages for the job ceiling | When stable programme LRA exceeds a valid, applicable selected ceiling, mark eligible windows strictly louder than P10 + ceiling. | This reuses the M19 high-passage threshold. Touching or overlapping marked windows describe passages to investigate. The test applies to the whole programme. A marked interval carries no local pass/fail, causal attribution or predicted benefit. |
| Upper percentile tail | An eligible observation after the zero-based P95 rank is in the upper rank tail. `aboveP95` means measurably louder. `upperRankTie` identifies observations assigned above that rank with the same LUFS as P95. | Window counts are discrete. Equal boundary observations need special treatment. The highlighted audio duration can be far from 5% of programme time. This describes short-term loudness. Clipping and true peaks are measured separately. |
| Quiet and gated passages | `belowP10` means strictly below P10 among eligible windows. `absoluteRejected` and `relativeRejected` identify separate gate outcomes. Every positive-energy window retains its absolute LUFS. `zeroEnergy` has no finite LUFS. | A window may be quiet within this programme and still be audible. Quiet/gated membership does not predict the effect of reducing the gain. Overlapping supports may carry several categories at once. |

The estimator orders the eligible population and uses the zero-based observation at `floor((N − 1) × p + 0.5)` for p = 0.10 or 0.95, without interpolation. LRA is P95 − P10. The qualified M4 diagnostic ordering uses full-precision energy with earlier window end first when energies tie. The estimator determines boundary *values*. Chronological assignment for an exact-energy tie makes the displayed upper ranks reproducible and conveys no loudness distinction. The P95 observation itself is part of the span. The existing M4 inclusive upper/lower diagnostic listings and the M19 low-passage rule retain their original definitions. [Population expressions](../../../Source/Core/Measurement/GatePopulation.h) · [Offline estimator](../../../Source/Core/Measurement/OfflineMeasurement.cpp) · [M4 attribution](../../../Source/Core/Proposal/AttributionEngine.cpp) · [M19 passage definition](../../../Source/Core/Proposal/LraPassages.cpp)

The LRA absolute gate includes energies at the −70 LUFS threshold. The relative gate includes energies at or above one hundredth of the mean of absolute-gated energies (20 LU below that mean loudness). Both comparisons operate on original energy. Below three seconds of real programme, duration takes precedence over gate classification, even if padding produced a window. A completed sub-60-second population may supply descriptive percentiles, with no excess-versus-ceiling claim. Silence and entirely below-gate audio have no P10/P95. Invalid requirements or applicability suppress target markers. A missing ceiling still permits gate and percentile views.

## Time and identity

Every measured LRA window has three seconds of support. Window starts are spaced by 100 ms from programme frame zero. The existing final 1.5 seconds of zero-input filter drain can create windows with measured ends beyond EOF. For a window ending at E, the displayed interval is [E − 3 × rate, min(E, real programme frames)). The exact measured end and padding flag remain available. Programme frames use the assembled/composed Source clock as applicable. An upper-tail window and a quiet window can overlap a given frame. Summing window lengths double-counts audio.

The accepted full-resolution snapshot and current session-cache format already retain chronological window ends and energies, gate, P10/P95 and metric status. The controller derives the index on its cancellable worker after validating the measured domain, runtime, content, layout, processing, build and complete window geometry. The timeline input selector filters invalid sources, unconfirmed layouts, stale Current and missing/in-progress measurements. An accepted prior measurement may still be shown while a new one is collecting, identified by its own measurement. A progressive curve or gain preview cannot supply measured LRA categories. New/Open, domain and audio edits revoke incompatible results. Target, viewport and layout changes can query the same accepted index.

## UI use and bounds

1. Opt in with `DiagnosticsController{true}`. Select `timelineMeasurement(session,domain,measuringThisDomain).snapshot` on the controller. The input state and controller status distinguish absence, changed processing, in-progress measurement and diagnostic preparation. Publish only a matching controller result.
2. From `result->lraTimeline`, use `target(session.getSelectedTargetProfile(), session.programmeApplicability)`. Its states are no ceiling, inapplicable target, unavailable population, unstable population, within ceiling and exceeds ceiling. `measured()` provides full-precision thresholds, programme metrics, stability, frames and measurement identity.
3. `columns(begin,end,pixels,target)` gives the union of exact overlapping window categories in each viewport column, plus finite loudness extrema and maximum eligible LUFS. `inspect(frame,target)` returns each overlapping observation with its individual flags, LUFS, chronological index, source span and padded end. Cache the viewport result by accepted index, target, time range and width. Equal-level ties and mixed categories should remain distinguishable.
4. The index shares the validated measurement. It adds two bytes per window on supported Macs and a summary tree over 32-window blocks. At the existing 24-hour ceiling there are at most 863,986 windows and 65,536 tree slots (under 6 MiB added on the supported 64-bit builds). A viewport contains at most 4,096 columns. Each column inspects up to 62 edge observations plus logarithmic block summaries. An exact frame inspection returns at most 30 windows. Construction reads cached measured windows once plus the bounded rank-tie and block-summary passes. There is no decoder, PCM buffer, waveform dependency or audio-file read in this path.
