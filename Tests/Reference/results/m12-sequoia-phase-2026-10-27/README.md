## Preserved history and reuse

The final coverage audit added two short schema-2 stereo/5.1 migration checks using
the same frozen ProgrammeTests binary. Exact settings, roles, profile, alignment
confirmation and gain bits survived schema-4 Save As; original files stayed
unchanged. The first supplemental oracle incorrectly required old millisecond
mtimes to survive the earlier Tucan move. Its native migration succeeded, but that
oracle failed; the corrected oracle permits verified locator/mtime refresh while
requiring identical content and all audible settings. The failed attempt remains
recorded; neither check changed production code or the frozen candidate.
`sequoia/schema2-migration-02/` and `auxiliary-tools/complete_with_migration.py`
close this coverage explicitly. The final completion receipt requires both these
supplemental cases and every base short/long/UI receipt.

Candidate-01 stopped at an outdated unscrollable-panel geometry assertion.
Candidate-02 corrected that test and stopped at noncanonical JSON in an audio-only
legacy fixture generated by the packager. Candidate-03 corrects the packager and
adds its regression. These failures are retained under `historical/`.

Production source, measurement build and app bytes are identical across all three
candidates. Only the M5 geometry-test executable changed between candidate-01 and
candidate-02; every native executable is identical between candidate-02 and -03.
Passing native receipts retain their original source/executable identity and reuse
chain. Silent UI was observed on candidate-01 and reused through exact app and
production-source equivalence; it is not represented as a fresh candidate-03 UI run.

See `sequoia/build-equivalence.json`, `change-impact-equivalence.json`, original UI
