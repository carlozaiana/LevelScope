# M19 impact-selected qualification plan

Recorded before implementation, 5 November 2026. Branch `codex/m19-lra-passages`,
published Intel checkpoint `c4eea6f1c4569ec4f31725694ddf34db8340f15e` plus its
documentation receipt. Main stays qualified M18 `51e47f300fcc38a386a5a92a7277029175cfab0c`.

## Affected contracts and fresh required checks

- New descriptive LRA grouping and bounded attenuation planning: exact windows,
  gating/percentile consistency, padding, deterministic scores/ties, limits and
  marker-density independence. Three-hour-sized synthetic population stress for
  <=64 MiB incremental storage, <=2 s Sequoia / <=5 s High Sierra grouping.
- New private assessment service calls shared verified-source preparation and
  existing gain/measurement workers. Check all selected requirements, exact-plan
  Apply authority, at most three passes/one copy, better-attempt retention, final
  positive global gain, realistic policy failures, unavailable/stale/cancelled
  inputs and full-precision bounds. Short stereo/5.1 fixtures at supported rates;
  other layouts remain explicitly unsupported for this new method.
- Session/proposal integration and M18 applied history: edits invalidate authority,
  inspection does not seek/play/mutate, Apply invalidates Current, independent
  measurement verifies, cancelled verification keeps applied gains unverified,
  save/reopen retains only historical explanations. Export still measures actual
  finalized PCM24 and requires both Current/artifact passes. Focused short export
  and sample-capture checks exercise all-channel processing including LFE.
- Run direct short measurement, section-proposal and job-requirements checks,
  plus focused UI/session/processing tests for changed callers. Preserve the
  ordinary peak-led method when LRA is unset. Adapt obsolete M17 tests that
  asserted all LRA correction was unavailable only for the newly supported case.
- Native silent UI: Source/Current passages, selection/highlight, explicit Assess,
  explanations, Apply/independent verification, cancellation and stale results.
  Device closed, routing muted; no video load/decoder/playback needed.

Stabilize with short targeted Sequoia runs. Freeze universal candidate (Intel
deployment minimum 10.13), then run the same selected binary/tests on actual
Golem 10.13.6. No Rosetta substitute. Record source/binary hashes, exact commands,
build/dependency/host identities, counters and resource measurements. Missing
required groups cannot produce a qualified summary. Recheck affected groups after
fixes, not a recursive M1–M18 runner.

## Real programme and listening

If available, use the original cinema source on Tucan read-only to choose a bounded
excerpt containing useful quiet/loud material. Record original content identity,
exact extraction frame range/roles and excerpt hash. Keep original and excerpt
audio out of GitHub. Plan one <=10-minute workflow per layout/host; the cinema
excerpt can supply the 5.1 case. An honestly explained policy-limited attempt is
acceptable; do not tune requirements merely to manufacture a pass.

Prepare before/after boundary listening segments from the measured candidate,
including at least an onset and return transition. The 100 ms convention is not
proof of perceptual transparency. Ask the user to coordinate outputs, level and
timing before any physical device opening. Keep numerical qualification and the
listening observation separately identified. No automatic physical/video run.

## Reuse, limits and budget

Reuse M18 and Intel checkpoint evidence only for unchanged measurement arithmetic,
input formats, transport/video, RF64 large-file handling and serial/parallel parity.
The new proposal consumes existing measured populations and existing processing;
it must not change measurement kernels or monitor/device behaviour. If edits reach
those contracts, record the concrete impact and add focused checks first.

No automatic full cinema, three-hour audio, codec matrices or historical endurance
runs. Estimate 1–2 hours selected qualification per Mac after build and about 5 GiB
scratch for bounded real audio/copies, plus <3 GiB universal build; measure actual
usage. No plugin targets/installations. Preserve all packages/tags/worktrees.
The inherited native completion pause remains accepted for Intel optimisation;
observe M19 cancellation/responsiveness and separately report new regressions.
Keep accepted occasional picture skips in the project contract, while no video
execution is planned for this audio/proposal-only change.

Publication and main integration of M19 require readiness review.

## Explicit executable selection

`Tests/Qualification/M19/run.py` calls only these direct groups: `core`,
`stereo`, `surround`, `rates`, `failures`, `inputs`, `gating`, `real`, plus
the short offline measurement suite, section-proposal `--smoke`, and the direct
job-requirements tests. It records executable hashes, build identity, platform,
commands, elapsed time and peak resident memory. Missing groups cannot satisfy
its automated-completion flag; that flag alone is not qualification. Native UI,
package integrity, cross-platform review and coordinated listening are separate.

The ten-minute stereo gating fixture supplies the sustained synthetic case;
the eight-minute 5.1 cinema excerpt supplies the real programme case. The latter
is exactly frames 77,760,000–100,800,000 (27:00–35:00 at 48 kHz) of the unchanged
original, with byte-identical PCM payload and conventional L/R/C/LFE/Ls/Rs roles.
Its explicitly chosen 15.0 LU example ceiling is a test requirement, not a new
delivery rule. A failing candidate remains inspectable but cannot Apply.

Diagnostic before/after float captures are eight seconds around selected onset
and return boundaries. They preserve the exact measured plan, with no dither,
monitor gain or hidden normalization. They are private listening fixtures,
not M10 published exports or delivery approvals. Any optional Left/Right-only
capture from 5.1 is explicitly partial, without downmix, and cannot establish
complete multichannel listening transparency.

Cross-platform comparison retains the established outer tolerances (0.01 LU/dB
for I/M/S/TP/SP and gain; 0.1 LU for LRA). Compare selected intervals, pass counts,
outcomes and requirements exactly, and report actual numerical differences.
These comparison tolerances never enter a profile verdict. Within each host,
candidate versus independent Current and injected samples versus the independent
processing oracle must agree exactly.
